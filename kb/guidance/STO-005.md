---
id: STO-005
title: Finished work kept open by a pending Timer
why_it_costs: The run's work is done, but it stays open, in Active Storage, until a long Timer fires.
fix: Race the Timer against the Signal or result, and return as soon as the work is done.
tradeoffs: None, unless something must happen when the Timer fires even after the work is done.

The run started a Timer of an hour or more, a Signal, Update, or Activity result arrived after it, and the run has been idle for at least an hour since, still waiting for the Timer.

The usual cause is a deadline Timer that the code waits on after the work finishes, instead of racing it. Select on both, cancel the Timer when the work wins, and return.

The estimate:

- active GB-hours saved = history bytes / 10⁹ × hours from the last result until the Timer fires
