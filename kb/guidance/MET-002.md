id: MET-002
title: Workflows queried far more often than anyone reads the answer
why_it_costs: Each Query a Worker receives is one Action, including the call-stack view in the Cloud UI. A dashboard or client that polls with Query pays one Action per open Workflow on every refresh.
fix: Read status with Describe, which isn't an Action, from the Workflow's status, memo, or Search Attributes. Read it once on the server and share it with every viewer instead of querying per viewer.
tradeoffs: Describe returns what the Workflow last recorded, not live in-memory state. If the Workflow upserts a Search Attribute for the UI to read, each upsert is an Action, so it saves Actions only when state changes less often than the UI would poll.

Queries arrive far more often than once every 15 minutes per open Workflow. That rate usually comes from a status page or a client loop that queries every open Workflow on a timer, sometimes once per browser tab.

Most status questions don't need a Query. Describe returns the Workflow's status, memo, and Search Attributes, and isn't an Action. Describe and List share a Visibility rate limit, so read once on the server and cache it for all viewers. Keep Queries for the rare case where someone needs live state that the Workflow hasn't recorded.

The saving keeps one Query an hour per open Workflow and counts the rest.
