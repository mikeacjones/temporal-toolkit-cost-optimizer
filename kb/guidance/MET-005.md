---
id: MET-005
title: Activities and Timers per start changed together after a deploy
why_it_costs: When a Workflow Type starts using more Activities and Timers per run, each run costs more Actions. A Timer-and-Activity loop that polls something is the usual cause, and it costs two Actions per check.
fix: Find the change that went out around the time the ratios moved. If it added a polling loop, poll with Activity retries instead, so each check is one Action, or check less often.
tradeoffs: Polling with Activity retries hides each attempt inside one Activity, so the Workflow history shows less detail. Longer intervals notice changes later.

Over the latest day, this Workflow Type's Activities per start and Timers per start both moved by a quarter or more, in the same direction, compared with the week before. That pattern lines up with a polling loop being added or removed. Check what was deployed when the ratios changed.

When the ratios rose, the finding estimates the Actions the change adds each month at the latest day's volume. When they fell, it reports the change without a saving, so you can confirm a fix landed.

A Timer followed by an Activity costs two Actions per check. An Activity that fails until the condition holds, with a fixed retry interval, costs one Action per check, and the Workflow waits on a single Activity.
