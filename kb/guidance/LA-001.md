---
id: LA-001
title: Local Activity retries billed after the first Workflow Task
why_it_costs: Local Activity attempts in the first Workflow Task share one Action. Once a Local Activity is still retrying past that Workflow Task, each further attempt is an Action, recorded in the Workflow Task's metering.
fix: Fix the failure that causes the retries. If the call is slow or flaky by nature, run it as a regular Activity, which retries on the server without holding the Workflow Task.
tradeoffs: A regular Activity adds a round trip through the server and an Activity task, so it's slower than a Local Activity that succeeds at once.

The Workflow Task metering in history shows Local Activity attempts that ran after the first Workflow Task. Those attempts are billed one Action each, and they keep the Workflow Task heartbeating while they run (LA-003).

Local Activities fit short calls that usually succeed the first time. A call that keeps failing for seconds belongs in a regular Activity, where the server handles the backoff.
