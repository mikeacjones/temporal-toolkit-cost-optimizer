---
id: CFG-010
title: A Schedule that starts a one-Activity Workflow
why_it_costs: The Schedule starts a Workflow that only wraps one Activity. A Standalone Activity would do the same work for one Action less per run.
fix: Switch the Schedule's target to a Standalone Activity once Schedules can start them, or start a Standalone Activity with a start delay from your own code if that fits.
tradeoffs: Schedules can't start Standalone Activities yet, so this is a fix to plan for. Starting from your own code gives up the Schedule's pause, backfill, and overlap policies.

The Schedule's target Workflow Type matches a WF-001 finding: each run starts a Workflow that runs one Activity and nothing else. A Standalone Activity runs the same Activity code without the Workflow around it.

tcopt flags these now so you can switch when Schedules support Standalone Activities. Check the feature's status for your SDK first.
