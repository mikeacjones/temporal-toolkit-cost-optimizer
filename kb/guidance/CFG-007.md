---
id: CFG-007
title: Frequent or one-shot Schedules
why_it_costs: Each Schedule run costs 3 Actions. A Workflow that sleeps between runs pays one Timer, and a start with a delay costs one start.
fix: For frequent runs, use a long-running Workflow that sleeps between iterations. For a single delayed run, start the Workflow with a start delay.
tradeoffs: A sleeping Workflow needs Continue-As-New to keep its history bounded, and you manage pause and backfill yourself. A start delay can't be paused or edited the way a Schedule can.

The Schedule runs every few minutes, or it runs once as a delayed start. A Schedule run costs 2 Actions for the Schedule plus 1 for the Workflow start.

For a Schedule that runs often, a single Workflow that loops and sleeps costs one Timer per iteration. For a Schedule created to run once, a Workflow start with a start delay costs one Action.
