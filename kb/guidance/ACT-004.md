---
id: ACT-004
title: Heartbeat volume
why_it_costs: Each Heartbeat that reaches the server is one Action. The SDKs send one at once and then at most one per 80% of the Heartbeat timeout, so a short timeout on a long Activity sends many.
fix: Raise the Heartbeat timeout to what you need for detecting a stuck Worker, and don't heartbeat from Activities that finish in seconds.
tradeoffs: A longer Heartbeat timeout means a crashed Worker is noticed later, and progress details update less often.

Heartbeats don't appear in Event History, so this finding is an estimate. tcopt takes how long the Activity ran and its Heartbeat timeout, and assumes the code heartbeats the whole time. The SDK throttles Heartbeats to one per 80% of the timeout, so calling RecordHeartbeat often isn't the problem. The timeout sets the volume.

The estimate compares today's timeout with a 1-minute timeout. Use the Cloud metrics (MET-001) to see the Heartbeat Actions this Workflow Type actually records.
