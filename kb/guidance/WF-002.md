title: Workflow that waits, then runs one Activity
why_it_costs: The Workflow start and the Timer are each an Action. A Standalone Activity with a start delay waits and runs for one Action.
fix: Start the Activity as a Standalone Activity with a start delay instead of a Workflow that sleeps and then runs it.
tradeoffs: Keep the Workflow if anything needs to cancel or change the wait from inside it, if clients query it, or if more steps are coming.

Each sampled run starts a Timer as its first command, waits for it to fire, then runs one Activity and closes. The start, the Timer, and the Activity are three Actions. A Standalone Activity started with `StartDelay` is one, so each run saves two.

Pass the wait as the start delay when the caller starts the Activity. The delay applies to the first attempt only; retries follow the retry policy.
