title: The same large header on every Activity
why_it_costs: Headers are stored with each Activity's input, so a large header is stored again for every Activity.
fix: Trim the header to what downstream code needs, such as trace and span IDs, or store the bulk once and pass a reference.
tradeoffs: Code that reads the removed header fields has to fetch them another way.

At least 3 Activities in the run carry an identical header of 1 KiB or more. Large headers usually come from a context propagator or interceptor that copies tracing baggage or a security token into every call.

Propagate only the IDs downstream code needs. If something large has to travel, store it once and put its key in the header.

The estimate keeps one copy and counts the rest:

- saved bytes = (copies − 1) × header bytes
- active and retained GB-hours are priced like STO-001, from each Activity's scheduled time
