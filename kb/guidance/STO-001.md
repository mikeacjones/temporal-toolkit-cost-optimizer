title: Large payloads
why_it_costs: Every input, result, and Signal payload is stored in history, in Active Storage while the run is open and Retained Storage after it closes.
fix: Store large data outside Temporal and pass a reference (the claim-check pattern).
tradeoffs: The external store adds a dependency, and its own storage and access controls. The data isn't visible in the Temporal UI.

The run carries Workflow inputs, Activity inputs or results, Signals, or Updates over 256 KiB. tcopt flags each payload over that size.

Write the data to an object store or database in the Activity that produces it, and return a key. The Activity that needs the data reads it by key.

The estimate assumes each large payload is replaced by a 256-byte reference:

- active GB-hours = (payload bytes − 256) / 10⁹ × hours from the event to the run's close, or to now while it's open
- retained GB-hours = (payload bytes − 256) / 10⁹ × the Namespace's retention hours, for closed runs
