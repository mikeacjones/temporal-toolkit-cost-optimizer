id: WF-001
title: Workflow that only wraps one Activity
why_it_costs: The Workflow start is an Action on top of the Activity. A Standalone Activity runs the same Activity for its own start alone.
fix: Start the Activity as a Standalone Activity from the client instead of starting a Workflow that runs it.
tradeoffs: You lose what only a Workflow gives you. Keep the Workflow if clients send it Queries (they don't show in history), if you want its Event History for the steps, or if more steps are coming.

Every sampled run of this Workflow Type starts, runs one Activity, and closes. It has no Timers, Signals, Updates, Child Workflows, Nexus Operations, or Search Attribute upserts. Starting the Workflow is one Action and scheduling the Activity is another. A Standalone Activity costs one Action to start, so each run saves one.

The Activity code doesn't change. The caller switches from starting a Workflow to starting the Activity, with the same retry policy and timeouts. The code locator lists the start call sites.

tcopt can't see Queries in history. Check that nothing queries this Workflow before you replace it.
