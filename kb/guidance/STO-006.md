title: Local Activity marker overhead
why_it_costs: Each Local Activity records a marker with its result, and on some SDKs its arguments, in history.
fix: Return smaller Local Activity results, and move work that doesn't fit Local Activities to regular Activities.
tradeoffs: Regular Activities take a round trip through the server, so they add latency. They also retry independently and run on any Worker polling the Task Queue.

Local Activity markers make up more than half of the run's history bytes. tcopt doesn't recommend Local Activities as a way to save cost, and this fix doesn't either: it shrinks what existing Local Activities record, or moves work that doesn't belong in them to regular Activities.

Local Activities fit short, latency-sensitive calls with small results. A Local Activity that returns a large document, or does long work, belongs in a regular Activity, or should store its output elsewhere and return a reference.

The estimate counts each marker's bytes above 1 KiB, which a smaller result would remove:

- saved bytes = Σ max(marker bytes − 1,024, 0)
- active and retained GB-hours are priced like STO-001, from the Workflow Task that recorded each marker
