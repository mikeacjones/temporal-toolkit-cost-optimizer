---
id: CHD-001
title: Child Workflow that runs one Activity
why_it_costs: Starting a Child Workflow is two Actions. The parent could schedule the same Activity itself, which costs what the child's Activity costs now.
fix: Call the Activity from the parent Workflow instead of starting a Child Workflow that runs it.
tradeoffs: A child gives the step its own Event History, its own Workflow ID, and its own timeouts and retry policy. Keep it when you need those, or when the child's history would otherwise push the parent toward its limits.

tcopt read the Child Workflow's history for each match. The child starts, runs one Activity, and closes, with no Timers, Signals, Updates, or children of its own. The parent pays two Actions to start it.

Schedule the Activity directly from the parent with the same options the child used. If several parents share the child's logic, move that logic into a function they call instead.
