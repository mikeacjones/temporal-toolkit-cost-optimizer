---
id: MET-001
title: More than one Heartbeat Action per Activity attempt
why_it_costs: Each Activity Heartbeat that reaches Temporal Cloud is one Action. Every SDK sends an Activity's first Heartbeat at once, and later ones at up to 80% of the Heartbeat timeout, so a short timeout on a long Activity, or any Heartbeat timeout on a short one, multiplies Actions.
fix: Leave the Heartbeat timeout off Activities that finish in seconds. For long Activities, set the Heartbeat timeout to how quickly you need to notice a dead Worker, not shorter.
tradeoffs: A longer Heartbeat timeout means a crashed Worker's Activity is retried later. Activities without a Heartbeat timeout only fail over when their Start-To-Close timeout expires.

The Workflow Type's Activities record more Heartbeat Actions than Activity attempts. Heartbeat volume follows the Heartbeat timeout, not how often the code calls Heartbeat: the SDK throttles calls to 80% of the timeout and sends the first one immediately. So a 10-second timeout on an Activity that runs for an hour costs about 450 Actions, and a Heartbeat timeout on an Activity that finishes in two seconds costs one extra Action every run.

Heartbeats only help Activities that run for minutes or longer, where you need to notice a dead Worker before the Start-To-Close timeout. Remove the Heartbeat timeout from short Activities, and set a longer one on long Activities. Under an Actions-per-second limit, Temporal Cloud drops Heartbeats first, so heartbeating more often doesn't make detection faster.
