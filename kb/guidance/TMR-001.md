title: Timer-plus-Activity polling loop
why_it_costs: Each poll costs 2 Actions, one for the Timer and one for the Activity.
fix: Poll from one Activity with a retry policy, so each poll is a retry and costs 1 Action, or poll less often.
tradeoffs: A retrying Activity shows one Activity with many attempts in history, not one event pair per poll. Attempts beyond the first aren't separate events.

The Workflow sleeps and then runs the same Activity, again and again, until the Activity reports what it's waiting for. tcopt flags it when the same Activity type follows a fired Timer at least 3 times in one run.

Move the wait into the Activity's retry policy. The Activity returns an error while the result isn't ready, and the retry policy's interval sets the polling rate. Each retry costs 1 Action and adds no events to history. For long waits between polls, keep the loop but poll less often.

The saving counts the loop's Timers, 1 Action each.
