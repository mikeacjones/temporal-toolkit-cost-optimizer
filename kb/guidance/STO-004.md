id: STO-004
title: Waiting in Active Storage
why_it_costs: While a run waits, its history stays in Active Storage, which costs far more per GB-hour than Retained Storage.
fix: Continue-As-New before the long wait, or complete the run and start the next step later with a start delay.
tradeoffs: Continuing as new needs the state passed as input. A start delay needs the caller, or a final Activity, to start the next Workflow.

The run is open, its history is over 256 KiB, and at least 80% of its open time is one wait of an hour or more: a pending Timer, or no events at all. Waits that end when work arrives after the Timer started are STO-005 instead.

Continue as new just before the wait, so the new run waits with an empty history. If nothing has to happen during the wait, finish the run and start the next one with a start delay.

The estimate:

- active GB-hours saved = history bytes / 10⁹ × the wait in hours (the pending Timer's duration, or the idle time so far)
