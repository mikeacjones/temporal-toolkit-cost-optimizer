id: ACT-006
title: Activities rejected by the wrong Worker
why_it_costs: When a Worker that doesn't register an Activity type polls its Task Queue, it fails the attempt and Temporal retries it. Each of those retries is one Action.
fix: Give each Worker build its own Task Queue, or use Worker Versioning, so only Workers that register an Activity receive it.
tradeoffs: A separate Task Queue needs its own Workers and routing. During a rollout, both builds need enough capacity on their queues.

An earlier attempt failed because the Worker that picked it up didn't register the Activity type, and a later attempt succeeded on a Worker that did. This usually happens during a rollout, when old and new Worker builds poll the same Task Queue, or when two services share a queue.

History only keeps the failure from the attempt just before the successful one, so tcopt sees the pattern when the last failure was the missing registration. The estimate counts every retry the Activity needed.
