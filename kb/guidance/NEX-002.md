---
id: NEX-002
title: Workflow that only calls one Nexus Operation
why_it_costs: The Workflow start is an Action on top of the Nexus Operation. A standalone Nexus Operation started from the client runs the operation without the Workflow.
fix: Start the Nexus Operation from the client with a Nexus client instead of a Workflow that calls it.
tradeoffs: Standalone Nexus Operations are experimental in the Go SDK and pre-release elsewhere, so this is advisory. Keep the Workflow if it will grow more steps, or if you rely on its history.

Each matching run starts, calls one Nexus Operation, and closes. It has no Activities, Timers, Signals, Updates, or Child Workflows. The Workflow start is one Action you can drop by starting the operation from the client.
