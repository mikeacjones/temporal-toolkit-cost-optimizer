---
id: ACT-002
title: Retrying errors that won't succeed
why_it_costs: Each retry is one Action. When every attempt fails with the same error, such as a validation error, a 4xx response, or bad credentials, the retries cost Actions and can't succeed.
fix: Mark errors that won't resolve on retry as non-retryable, either by returning a non-retryable Application Error or by listing the type in NonRetryableErrorTypes.
tradeoffs: A non-retryable error fails the Activity at once. If the same message can sometimes be transient, keep it retryable and cap the attempts instead.

The Activity's last two attempts failed with the same error type and message, and the Activity gave up after running out of attempts. History only keeps the last two failures, so tcopt can't prove the earlier ones matched, which is why this finding is medium confidence.

Errors like "card declined", "invalid argument", or "unauthorized" don't change between attempts. Return them as non-retryable, or add their type to the Retry Policy's NonRetryableErrorTypes, and the Activity fails after one attempt.

The estimate counts every retry after the first attempt.
