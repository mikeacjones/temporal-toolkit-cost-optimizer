title: Long-running Workflow without Continue-As-New
why_it_costs: An open run's whole history sits in Active Storage, which costs far more per GB-hour than Retained Storage, and it keeps growing.
fix: Continue-As-New at a natural boundary, such as a day or a batch, so earlier history moves to Retained Storage.
tradeoffs: State has to pass to the new run as input. Signals and Updates in flight need handling before the run continues as new.

The run has been open more than 2 days, its history is over 256 KiB, it recorded an event in the last day, and it didn't start from Continue-As-New.

Continue as new when `workflow.GetInfo(ctx).GetContinueAsNewSuggested()` is true, or at a natural boundary in the Workflow's own logic.

The estimate assumes the history grew evenly over the T hours the run has been open, and that the fix continues as new every 24 hours:

- active GB-hours saved = history bytes / 10⁹ × (T − 24) / 2

Earlier runs move to Retained Storage, where the whole history would go anyway when the run closes, so retained storage isn't counted.
